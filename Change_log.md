## Сущности БД для задания 7

Основные таблицы уже существуют — создавать второй механизм приглашений не нужно.

```text
users
 ├── 1:1 candidate_profiles ── 1:N offers N:1 ── employer_profiles 1:1 ── users
 └── email, role, is_active

candidate_profiles
 ├── phone, full_name, is_searchable
 ├── 1:N candidate_skills
 ├── 1:N candidate_experiences
 ├── 1:N candidate_categories ── N:1 categories
 │                                  ├── specialization_id → specializations
 │                                  └── grade_id → grades
 └── 1:N fsp_achievements
```

| Сущность | Нужные поля для задания 7 |
| --- | --- |
| `Offer` | `employer_profile_id`, `candidate_profile_id`, `title`, `description`, `salary_from`, `salary_to`, `salary_currency`, `salary_gross`, `contact_method`, `status`, даты |
| `EmployerProfile` | Название компании, описание, сайт, контакты компании |
| `CandidateProfile` | ID кандидата, имя, публикация; телефон раскрывается после принятия |
| `User` | Роль, принадлежность профиля, активность; email кандидата для раскрытия контактов |
| `CandidateCategory` | `is_current`, `status`, `category_id`, `test_score` — контекст выбранного кандидата |

Статусы предложения: `sent → viewed → accepted / rejected`; ответ также допускается непосредственно из `sent`. Конечный статус нельзя перезаписать повторным ответом.

Ближайшая работа по заданию 7: подключить форму в `app/templates/matching/detail.html` к существующему `POST /employer/offers`, показать ошибки формы и использовать уже готовые списки и ответы. Основная логика находится в `app/modules/employers/service.py`, API — в `app/modules/employers/offers_router.py`, ответы кандидата — в `app/modules/candidates/offers_router.py` и `app/modules/candidates/offers_web.py`.
