# Пробный дизайн FSP IT Talent Match

Дата проверки: 09.10.2026. Интерфейс выполнен на Jinja2, CSS, локальном HTMX и небольшом JavaScript. React, сборщик и новая инфраструктура не добавлены.

## Просмотр

Запущен локальный Uvicorn: **http://127.0.0.1:8010/**.

- Обзор прототипов: http://127.0.0.1:8010/design-preview
- Кандидат: http://127.0.0.1:8010/design-preview/candidate
- Работодатель: http://127.0.0.1:8010/design-preview/employer
- Поиск: http://127.0.0.1:8010/design-preview/search
- Профили с ФСП и без ФСП: `/design-preview/person/1`, `/design-preview/person/2`.
- Приглашение: `/design-preview/invitation`; выбор другого кандидата — `?candidate=2`.
- ФСП, резюме, приватность: `/design-preview/fsp`, `/design-preview/resume`, `/design-preview/privacy`.
- Настоящие формы: `/auth/login`, `/auth/register`, `/auth/check-email`, `/auth/verify?token=...`.
- Настоящие защищённые экраны: `/candidate/profile`, `/employer/profile`, `/assessments`, `/assessments/start`, `/assessments/attempt/{id}`, `/assessments/attempt/{id}/finish`, `/assessments/attempt/{id}/result`. Требуют настоящего входа и PostgreSQL.

Для повторного запуска в обычном окружении проекта:

```powershell
uv run --locked uvicorn app.main:app --host 127.0.0.1 --port 8010
```

Этот запуск не вызывает `app.start` и не применяет миграции. Текущий прогон использовал временное окружение Python 3.12.15 вне проекта с зависимостями из `uv.lock`.

## Что является прототипом

Отдельный `app/web/design_preview.py` содержит только GET-маршруты и синтетические записи. Роутер не зависит от БД, auth-сервисов или модулей бизнес-логики. Он исключён из OpenAPI. На каждом экране есть постоянная маркировка демонстрации.

Поиск фильтрует три вымышленных профиля в браузере. Профиль объясняет соответствие по категории, тестам и достижениям; отсутствие истории ФСП не снижает полноту представления кандидата.

Демо-приглашение содержит компанию, описание, диапазон зарплаты в рублях и способ связи. Принятие/отказ и настройки сохраняются только в `sessionStorage` текущей вкладки с отдельным префиксом `fsp-design-preview:`. Реальные сообщения не отправляются. Контакт синтетический; открывается после принятия и при включённом демо-согласии. Это визуальное правило, не реализация серверной защиты.

Демо-потребность не публикует вакансию. Таблица работодателя показывает статические примеры статусов. Настройки видимости/приглашений/достижений являются визуальными предпочтениями, не правами настоящего аккаунта; согласие на контакты влияет на демонстрационное отображение.

Демо-ФСП показывает привязку и импорт без HTTP-запросов к реестру. Достижение явно синтетическое. Повторное действие не создаёт новый блок.

Резюме — макет с печатными стилями. Кнопка вызывает печать браузера, где можно сохранить макет в PDF. Генератор PDF настоящего пользователя не реализован.

Проверено:

- Фильтры, пустая выдача и сброс.
- Принятие, отказ, неизменность завершённого решения и сброс демо.
- Скрытие контактов до принятия, открытие после него и скрытие при отключённом согласии.
- Ошибка диапазона зарплаты в демо-форме, демо-отправка, повторный ФСП-импорт.
- Вызов печати и печатные стили макета резюме. Реальная загрузка PDF не проверялась.
- Нативная валидация существующей регистрации и сохранение параметра `next` входа.
- Отсутствие ошибок JavaScript и горизонтального переполнения документа на 1440, 390 и 320 px. Таблицы при необходимости прокручиваются внутри своего контейнера.
- Сохранение исходных контрактов семи групп рабочих форм. Базовые контракты зафиксированы из исходных шаблонов в `tests/fixtures/working_form_contracts.json`.
- Рабочие шаблоны кандидата, компании, всех шагов тестирования, пустой истории, ошибок auth и подтверждения email отрисованы в браузере с тестовыми фикстурами. Фикстуры существуют только в тесте; браузер перехватывает тестовый URL внутри `/design-preview/__test-render/`. Такого серверного маршрута нет. Скриншоты помечены «Тестовый рендер рабочего шаблона · фикстуры · без БД».
- Для пяти рабочих форм браузер отправил исходный POST/action и ожидаемые поля. Все POST перехвачены до сети, в БД ничего не записано. Это проверяет взаимодействие формы, а не сохранение данных.
- GET всех demo-страниц работает с зависимостью, запрещающей обращения к БД; POST на демо-экраны возвращает 405; неизвестные экраны/профили возвращают 404.

Docker Engine недоступен: отсутствует pipe `dockerDesktopLinuxEngine`. В проекте нет подтверждённой отдельной PostgreSQL для тестов. Поэтому не запускались запись профилей, реальная регистрация/вход, подтверждение токена, SMTP/Mailpit, сохранение/расчёт попытки через БД, integration и пять auth E2E. Миграции не применялись, существующие volumes/данные не изменялись.

Вёрстка защищённых экранов проверена фикстурами; фактический авторизованный пользовательский путь на PostgreSQL не подтверждён этим прогоном.

## Backend-дефекты и расхождения, оставленные без изменений

- HTML auth/profile обходит часть Pydantic-валидации API; частичный PATCH зарплаты, даты обновления опыта, `null` обязательных полей и конфликт переименования навыка требуют отдельной backend-задачи.
- Вход допускается до подтверждения email, хотя описание регистрации обещает иной порядок.
- `sql_group_by` в `app/modules/assessments/seed/backend_junior.json` имеет правильный ответ `COUNT`, которого нет среди вариантов.
- Загрузка вопросов не включена в startup; на новой БД одного применения миграций недостаточно для прохождения теста.
- Провал заменяет текущую подтверждённую категорию; условная проверка cooldown допускает обход. Конкурентные старты/финиши требуют отдельной проверки и атомарности.
- Сообщение «попытка не сгорает» не соответствует подсчёту всех провалов. В этой работе оно сохранено; правила и расчёт не менялись.
- Согласование формулы, порогов и cooldown не подтверждено доступными документами. Недоступный документ созвона мог содержать уточнения.
- Миграция snapshot не содержит переноса существующих строк; DB default `answered_at` расходится с моделью. Текущий ORM явно записывает NULL, поэтому default сам по себе не доказывает поломку старта.
- Backend поиска, предложений, ФСП/PDF и приватности отсутствует. Дизайн не выдаёт его за готовую интеграцию.
